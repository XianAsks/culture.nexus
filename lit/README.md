# lit/ — retrieved literature

Source PDFs and search provenance for the Spirit project. Register: `../resources.md`.
Method: `../methods.md`. License notices: `../.licenses/`.

Everything here was retrieved on **2026-08-23** using two skills from the
`google-deepmind` bundle. Both sources are laid out identically.

---

## Structure

```
lit/
├── README.md          this file
├── WANTED.md          verified to exist but not held — the acquisition list
├── normalize.sh       idempotent tidy-up; re-run after any new retrieval
├── normalize.py         └─ all its logic (stdlib only)
├── .gitignore         excludes */pdf/ — see "Size and version control"
│
├── openalex/          scholarly database — broad coverage, humanities included
│   ├── MANIFEST.md      what was retrieved: title, venue, license, version, DOI, file
│   ├── QUERIES.md       what was searched, with hit counts and zero-hit results
│   ├── queries/         raw API responses, one JSON per query (NN-slug.json)
│   ├── meta/            machine-readable records used to build MANIFEST.md
│   │   ├── records.json   full metadata incl. license and OA location
│   │   └── selection.json the works hand-picked for download
│   └── pdf/             YYYY-short-title-Wxxxxxxxx.pdf
│
└── epmc/              Europe PMC — life sciences only, open access only
    ├── MANIFEST.md
    ├── QUERIES.md
    ├── queries/
    ├── meta/            download-tail.log — log of the trailing background batch
    └── pdf/             YYYY-short-title-PMCxxxxxxx.pdf
```

**Filename convention** (both sources): `YYYY-short-title-ID.pdf`. The trailing ID is
authoritative — `W…` is an OpenAlex work ID, `PMC…` a PubMed Central ID. The slug is
for human legibility only and is regenerated by `normalize.sh`; never key anything off it.

## What each source is for

| | OpenAlex | Europe PMC |
|---|---|---|
| **Covers** | all disciplines, incl. Tibetology, religious studies, art history | life sciences only |
| **Access** | open and closed; metadata for both | open access only (enforced by the skill) |
| **Good for** | verifying citations; finding humanities articles | ancient DNA, bioarchaeology, contemplative science |
| **Weak at** | monographs are metadata-only, rarely PDFs | anything textual, historical, or art-historical |
| **Query echo** | yes — `meta.x_query.oql` in each response | no — queries transcribed into `QUERIES.md` by hand |

Between them: **OpenAlex verifies this project's citations but will not deliver its
core literature** (the monographs are closed); **Europe PMC covers the etic half of
the project and nothing else**. Neither reaches Tibetan-language sources at all.

## Usage

Prerequisite for both: `uv` on PATH. The OpenAlex skill additionally reads
`OPENALEX_API_KEY` from `~/.env` — **not** from this project's `.env.api`, which the
CLI never looks at (`openalex_cli.py` hardcodes `~/.env`).

> **`~/.env` is not shell-sourceable.** It holds saved query strings as well as keys, and at least
> one contains brackets and a comma, so `set -a; . ~/.env` fails under zsh with "no matches found".
> The CLI reads it with python-dotenv, which handles it correctly. To get the key into the
> environment for an ad-hoc command, extract just that line:
> `export OPENALEX_API_KEY=$(grep -m1 '^OPENALEX_API_KEY=' ~/.env | cut -d= -f2-)`

```bash
# Invoke via the skills, not by calling the APIs directly:
#   /google-deepmind:literature_search_openalex
#   /google-deepmind:literature_search_europepmc

# After any new retrieval, from lit/:
./normalize.sh          # renames new PDFs, regenerates both MANIFEST.md files
```

`normalize.sh` is a one-line wrapper around `normalize.py`, which uses only the
standard library. Run either.

It is idempotent and derives everything from `queries/` and `meta/`, so re-running
is always safe. It does **not** rewrite two hand-maintained files: `QUERIES.md`,
which records the queries actually issued, and `WANTED.md`.

To reproduce or extend a search, read the query text from the relevant
`QUERIES.md` row and re-issue it; raw responses in `queries/` show exactly what
came back, including for queries that returned nothing.

## Conventions

- **Zero-hit queries are kept.** A search that returned nothing is evidence that the
  search was run — see `methods.md` §7 on negative results. They appear in `QUERIES.md`
  under "Zero-hit queries" and as ~60-byte files in `queries/`.
- **Noisy queries are kept and labelled.** Europe PMC's `QUERIES.md` flags three queries
  whose booleans were swallowed, returning thousands of irrelevant clinical hits. Kept as
  evidence of method, not as findings.
- **Licenses are recorded, not verified.** Both MANIFESTs carry the license string the
  API reported. `unspecified` means none was declared — assume all rights reserved.
  Several files are `submittedVersion` preprints, not the version of record.
- **Verified is not the same as held.** `WANTED.md` lists items whose citation details
  are confirmed by a database lookup but whose full text we do not have. It is distinct
  from `../resources.md` §17, which lists things searched for and *not* confirmed to
  exist. Note the trap it documents: for two monographs, what OpenAlex indexes is a
  *review of the book*, not the book — easy to mistake for the work itself.
- **Nothing here is a finding.** These are sources. Claims derived from them belong in
  `../resources.md` with an `#e/` tag, and the reasoning in `../background.md`.

## Size and version control

The PDF directories are large — one Europe PMC paper (the Tianshanbeilu isotope
review) is 182 MB by itself. Two `.gitignore` files handle this, each placed next
to what it governs:

| File | Excludes |
|---|---|
| `../.gitignore` | `.env*` (defensive — the OpenAlex key lives at `~/.env`, outside the repo; no `.env.api` exists here), `*.err`, `*.tmp` |
| `lit/.gitignore` | `*/pdf/` — now also covers `direct/pdf/` |

## Subdirectories added 2026-08-27

| Dir | What | Provenance record |
|---|---|---|
| `wikipedia/` | citation harvesting from encyclopedia articles — the instrument against `../resources.md` §17.1's monograph gap | `wikipedia/README.md`; per-article JSON in `harvest/` |
| `direct/` | open-access items fetched by URL, where neither database skill could deliver the file | `direct/MANIFEST.md`, per item |

Both follow the existing rule: full texts under a `pdf/` directory and gitignored;
manifests and query records committed.

Tracked: both MANIFESTs, both QUERIES logs, `queries/`, `meta/`, `WANTED.md`,
this file, and the normalize scripts. Every PDF is reconstructible from the DOIs
and IDs those record, so nothing is lost by excluding the binaries.

The project is **not yet a git repository**; these rules take effect on `git init`.
They were verified against a throwaway repo with the same layout.
